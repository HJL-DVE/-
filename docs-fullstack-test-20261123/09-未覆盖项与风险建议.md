## 二、风险建议

### R-01 internal-token 有可预测默认值（生产风险）

```yaml
# 全部 19 处配置一致：
internal-token: ${INTERNAL_TOKEN:teaclub-internal-default-token}
```

- **风险**：生产环境若忘记设置 `INTERNAL_TOKEN` 环境变量，所有服务会用同一个公开可预测的令牌。内部令牌可绕过业务层直连服务端口（`/api/*/internal/**` 不在网关白名单，但直连端口可访问），可能被用于越权调用。
- **建议**：① 生产部署脚本强制校验 `INTERNAL_TOKEN` 非默认值；② 把默认值改为空并让服务启动时校验「为空则拒绝启动」；③ 内部令牌改用 mTLS 或请求签名。
- **级别**：中（当前为课程设计/内网环境）

### R-02 application-local.yml 硬编码 dev 密钥

- 密钥内容明确标注 `do-not-use-in-production`，且 `application-local.yml` 仅在 `local` profile 激活（生产用 `docker` profile）。
- **建议**：保持现状但加注释说明；或把 dev 密钥移到 `.env.local`（已 gitignore）。
- **级别**：低

### R-03 生产未接入真实微信支付

- 当前为 Mock 渠道（`teaclub.payment.provider=mock`），保留了验签/幂等/状态机的真实逻辑，切换真实渠道只需换 Provider 实现。
- **建议**：答辩时明确说明这是设计取舍，并展示 Provider 抽象层作为可替换性证据。
- **级别**：低（已知范围）

### R-04 无监控与告警

- DLQ 有重放机制但无告警；服务异常只能靠人工看日志。
- **建议**：接入 Spring Boot Actuator（项目已有）+ Prometheus 采集；DLQ 深度 > 0 时告警。
- **级别**：中（生产化必需）

### R-05 报表为实时跨库聚合

- report-service 用跨库 SELECT-only 账号实时聚合，数据量大时压力落在业务库。
- **建议**：引入物化视图或定时预聚合；或在业务服务补统计接口走 Feign（`ReportFeignClient` 已预留但未启用）。
- **级别**：中（数据量增长后）

### R-06 回归脚本存在共享数据干扰

- 24 号脚本故意 RENAME 表制造 DLQ 失败场景；若中途崩溃会破坏会员域（本次已实际发生并导致 17 个脚本连环失败）。已加进程守护。
- **建议**：把「破坏性测试」拆到独立库执行，避免影响主回归链。
- **级别**：中（已缓解）

### R-07 小程序单包体积

- 28 个页面未分包，主包体积接近微信 2MB 限制（当前产物大小需实测）。
- **建议**：按业务拆分包（首页+点单 / 订单 / 会员 / 营销）。
- **级别**：低（当前可发布）
