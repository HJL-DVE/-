## 六、⚠️ 发现的问题

### P2-03 小程序 BASE_URL 硬编码局域网 IP（未修复，需发布流程配合）

```ts
// src/utils/request.ts
export const BASE_URL = 'http://192.168.3.34:9000'
```

- 小程序工程**没有 .env 机制**（管理后台有 `.env.development` / `.env.production`）
- 换网络环境（换 WiFi / 换机器）即失效；真机必须与电脑同局域网
- 小程序正式发布后 `http://` 明文域名还会被微信平台拦截（必须 HTTPS + 备案域名）

**建议**（涉及发布流程，未擅自改动）：

1. 引入 `.env` + `VITE_GATEWAY_URL`，与 uni-app 的 `import.meta.env` 机制对齐；
2. 生产环境改为 `https://api.你的域名`，并在微信后台配置 request 合法域名；
3. 或提供「自定义服务器地址」入口（类似小程序调试面板），便于现场演示。

## 七、真机与开发者工具差异风险

| 差异点 | 说明 | 建议 |
| --- | --- | --- |
| 127.0.0.1 vs 局域网 IP | 模拟器可用 127.0.0.1，真机必须用局域网 IP | 已在代码注释中说明 |
| 不校验合法域名 | 开发者工具勾选「不校验」；真机/上线必须 HTTPS | 已在 project.config.json 设 urlCheck=false（仅开发期） |
| wx.login code | 开发者工具返回模拟 code；真机返回真实 code | 后端 mock code2session，需真机接入真实微信 |
| 图片资源 | 包内 `/static/images/`（8 张，按品类复用） | 正式发布建议迁 OSS/CDN |
| 分包 | 28 页**未分包**，单包体积偏大 | 微信主包上限 2MB，建议按业务分包 |
