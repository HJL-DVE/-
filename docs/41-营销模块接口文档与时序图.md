### 1.4 事件（RabbitMQ，exchange=teaclub.business.exchange）

| 事件 | 生产者 | 消费者 | 行为 |
| --- | --- | --- | --- |
| ORDER_PAID (rk=order.paid) | order-service | member / marketing | member 更新消费档案；marketing 发消费积分+触发满赠/门店活动 |
| REFUND_SUCCEEDED (rk=refund.succeeded) | payment-service | marketing | 按 ORDER_EARN 原流水冲正积分 |
| 失败处理 | — | all | nack(requeue=false) 进 DLQ，DlqReplayScheduler 每 15s 重放（≤5 次） |

## 二、关键链路时序图

### 2.1 订单支付 → 积分发放 + 满赠活动

```text
会员          order         payment       RabbitMQ        member       marketing
 │ 支付订单     │              │              │              │             │
 │────────────>│ 钱包扣款     │              │              │             │
 │             │──PAID────────│              │              │             │
 │             │ outbox:ORDER_PAID           │              │             │
 │             │─────────────────────────────>│              │             │
 │             │              │   route order.paid          │             │
 │             │              │──────────────>│              │             │
 │             │              │              │──投递────────>│             │
 │             │              │              │──投递─────────────────────>│
 │             │              │              │              │ 消费档案+X  │ 发消费积分
 │             │              │              │              │             │ 满赠活动判定
 │             │              │              │              │             │ 发券+活动积分
 │             │              │              │              │<─快照回写───│
 │<────────────积分到账通知（小程序轮询）─────────────────────│             │
```

消费失败时（例如 member 库表异常）：

```text
consumer: handle 抛异常
  ├─ 释放 Inbox 认领（DELETE sys_inbox_message）
  ├─ basicNack(requeue=false)
  │     └─ DLX → teaclub.member.order-paid.queue.dlq
  └─ DlqReplayScheduler(15s)
        ├─ x-death.count <= 5 → 重放原队列 → 重新消费
        └─ 超限 → 保留 DLQ + ERROR 日志（人工介入）
```

### 2.2 领券（三层幂等）

```text
小程序          gateway      marketing       Redis         MySQL
 │ 领券          │             │              │             │
 │─────────────>│ JWT 校验    │              │             │
 │             │────────────>│              │             │
 │             │             │ 1. receive 锁  │             │
 │             │             │─setIfAbsent──>│ 800ms TTL   │
 │             │             │ 2. 限领校验    │             │
 │             │             │─SELECT COUNT──────────────>│ receive_record
 │             │             │ 3. 发行计数    │             │
 │             │             │─UPDATE issued+1(条件)──────>│ template
 │             │             │ 4. 写券实例    │             │
 │             │             │─INSERT─────────────────────>│ coupon
 │             │             │ 5. 领取流水    │             │
 │             │             │─INSERT─────────────────────>│ receive_record
 │<────────────┼─────────────┤  │             │
```

### 2.3 积分商城兑换（原子性）

```text
小程序       marketing                                MySQL
 │ 兑换        │                                         │
 │───────────>│ BEGIN                                   │
 │            │ 1. 限兑校验(exchange 记录 count)          │
 │            │ 2. 扣库存: UPDATE stock=stock-1          │
 │            │      WHERE stock>=qty OR stock=-1       │
 │            │ 3. 扣积分: UPDATE total_points=total-30  │
 │            │      WHERE total_points>=cost  ←不足即异常│
 │            │ 4. 写兑换记录 exchange                   │
 │            │ 5. 券类商品: grant() 发券                │
 │            │ COMMIT  ←任一步失败整体回滚              │
 │<───────────┤ exchangeNo + remainPoints + couponNo    │
```

### 2.4 退款积分冲正

```text
payment      RabbitMQ       marketing            MySQL
 │ 退款成功     │              │                    │
 │─REFUND_SUCCEEDED──────────>│                    │
 │             │   route refund.succeeded          │
 │             │─────────────>│                    │
 │             │              │ 查该订单 ORDER_EARN │
 │             │              │ 原流水金额 X        │
 │             │              │ 写 ORDER_REFUND_REVERSE -X
 │             │              │（不重算，按原额）    │
 │             │              │ 重复回调：唯一键拦截 │
```

## 三、错误码（营销模块）

| code | 场景 |
| --- | --- |
| 0 | 成功 |
| 10002 | 券已被其他订单使用 / 状态不允许 |
| 10403 | 操作过于频繁（领券 800ms 锁） |
| 400x | 参数非法（面额>=门槛、非法券类型等，见 40 文档） |

## 四、幂等设计汇总

| 层 | 机制 | 键 |
| --- | --- | --- |
| Redis 预筛 | markConsumed 仅成功后写入 | mq:consumed:{queueName}:{eventId}（按消费者隔离） |
| Inbox | tryClaim 与业务同事务，失败释放 | sys_inbox_message.event_id PK |
| 券 | 条件 UPDATE + 唯一键 | uk_coupon_no / uk_points_biz |
| 活动 | 参与记录先行 | uk_activity_member_biz(activity_id,member_id,biz_no) |
| 资金 | uk_txn_biz | (biz_type,biz_no) |
