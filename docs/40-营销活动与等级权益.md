## 一、交付内容

### 1.1 优惠券模板管理（CRUD）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/admin/marketing/coupons/templates` | 新建模板 |
| PUT | `.../templates/{id}` | 编辑 |
| DELETE | `.../templates/{id}` | 删除 |
| PUT | `.../templates/{id}/status?status=` | 启用/停用 |
| GET | `.../templates/{id}` | 详情（含门店/商品/等级范围） |

**两条关键业务规则**：

| 规则 | 原因 |
| --- | --- |
| 已发行（issuedCount > 0）的模板只允许改名称、发行量、状态、说明、限领数 | 券实例领取时把面额/门槛/折扣率**冗余**到了 mkt_coupon，改模板会造成同模板下不同批次权益不一致，对账无法解释 |
| 已发行的模板**不允许删除** | 券还在会员手里，删模板会让券失去来源。只能停用 |

模板校验（实测全部生效）：

- 满减券：面额必须 > 0 且 **小于门槛**
- 折扣券：折扣率必须 0 < rate < 10000
- 兑换券：必须指定 SPU 或 SKU
- 门店券：必须配置适用门店
- 商品券：必须配置适用商品

### 1.2 会员等级权益

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/marketing/level-benefits` | 全部等级权益（按等级分组） |
| GET | `.../level/{levelId}` | 某等级权益 |
| POST | `.../level-benefits` | 新增或更新（同等级同编码唯一） |
| DELETE | `.../level-benefits/{id}` | 删除 |
| GET | `/api/marketing/level-benefits/level/{levelId}` | 会员端查询 |

**权益编码**：BIRTHDAY_COUPON、POINT_RATE（倍率 ×100）、BIRTHDAY_POINTS、EXCLUSIVE_COUPON、PRIORITY_SERVICE。

> **等级定义不在本服务**：等级名称、升级门槛、折扣率仍在 member-service 的 mem_member_level。
> marketing-service 只维护「营销侧权益」，避免两个服务同时管一份等级数据。

**奖励配置**（config_json，8 类活动共用）：

```json
{"thresholdAmount":3000,"couponTemplateIds":[3],"points":50,"continuousDays":7,"description":"满30送券+50积分"}
```

**发放流程**（同一事务，三步）：

```text
1. 写参与记录 → uk_activity_member_biz(activity_id, member_id, biz_no) 拦重复
2. 占活动名额 → used_quota 原子 +1（total_quota=0 表示不限）
3. 发券 / 发积分
```

> **为什么参与记录在发奖之前**：唯一键冲突是「重复参与」最可靠的信号。
> 先写记录能避免重复发券（券比积分更难回退）。

### 1.4 积分商城

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/marketing/points-goods` | 商品列表 |
| POST/PUT/DELETE | `.../points-goods[/{id}]` | 增改删 |
| GET | `/api/marketing/points-goods` | 会员端商品列表 |
| POST | `/api/marketing/points-goods/{id}/exchange` | 兑换 |
| GET | `.../points-goods/exchanges` | 我的兑换记录 |

**兑换的原子性**：

```text
1. 限兑校验（每人限兑次数）
2. 扣库存  → 条件 UPDATE: stock >= qty 或 stock = -1（不限）
3. 扣积分  → 条件 UPDATE: total_points >= cost
4. 写兑换记录
5. 券类商品发券
```

全部同一事务：任一步失败整体回滚，不会出现「扣了积分没拿到货」或「扣了库存没扣积分」。

## 四、退款与活动积分的口径（重要）

**退款只冲正消费积分（ORDER_EARN），不冲正活动奖励积分。**

原因：活动奖励是对「参与活动」这件事的回报，与订单是否退款无关；
而且券可能已被使用，回退活动积分会造成口径混乱。

因此脚本 23 的断言改为**按该订单 ORDER_EARN 流水的实际值**计算应扣额，
而不是「订单前后的总积分差」——后者会把同单触发的活动积分也算进去（实测踩过）。
