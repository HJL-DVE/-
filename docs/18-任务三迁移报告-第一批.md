## 1. 数据迁移

### 1.1 备份

`infrastructure/migration/backup/teaclub_before_migration_20261119_1945.sql`（453 KB，28 条 INSERT）

### 1.2 迁移映射

见 `infrastructure/migration/MIGRATION-MAPPING.md`。核心原则：

- **保留历史 ID**：目标表不重排自增，直接搬原值
- **不触发业务事件**：只做 INSERT，不调用任何业务接口
- **分库隔离**：每个服务只搬属于自己的表

```text
node infrastructure/migration/migrate.js --dry-run   # 看计划

node infrastructure/migration/migrate.js --force     # 强制重做（不按行数跳过）
node infrastructure/migration/verify.js              # 校验
```

> **跨实例迁移不能用 `INSERT ... SELECT`**（3306 → 3307 是不同实例），

### 1.6 冻结方案（不通过改余额模拟）

源表 `wal_wallet` 已有 `status` 字段（NORMAL/FROZEN），**直接迁移该字段**，
不新增列、不改余额。

若后续需部分金额冻结（如冻结 10 元但余额 100 元），应新增独立的
`wal_wallet_freeze` 冻结记录表（可用余额 = 余额 - 冻结额），
**不得直接修改 `principal_balance`** —— 那会破坏"余额 = 流水累计"不变量。

## 2. wallet-service 资金业务迁移

### 2.1 迁移清单

从单体 `backend/src/main/java/com/teaclub/wallet/` 迁移 36 个文件：

| 类型 | 文件 | 说明 |
| --- | --- | --- |
| 实体 | WalWallet, WalWalletTransaction, WalRechargeOrder, WalRechargePlan, WalRechargePlanStore | 表名与列名不变 |
| 枚举 | WalletBizType, DeductOrder | 幂等键类型与扣款顺序 |
| DTO | RechargeInCmd, ConsumeOutCmd, RefundInCmd, WalletChangeResult 等 8 个 | 命令对象 |
| Mapper | WalWalletMapper（含 FOR UPDATE 行锁）, WalWalletTransactionMapper 等 5 个 | 行锁是并发控制核心 |
| Service | WalletService 接口 + WalletServiceImpl 实现 | 资金唯一入口 |

**改动点**：

1. 包名 `com.teaclub.wallet` → `com.teaclub.cloud.wallet`
2. `com.teaclub.common.*` → `com.teaclub.cloud.core.*`
3. **品牌扣款顺序**原从 `sys_brand` 表直接读（跨库）→ 改为
   **Feign 调用 auth-service** + Redis 缓存 60 秒
4. 增加 `HotDataCache.evictWallet` 缓存失效（资金变动后）
5. `MyMetaObjectHandler` 迁到 common-core（各服务共用）

### 2.2 并发与幂等设计（未改动，仅迁移）

| 机制 | 实现 |
| --- | --- |
| 并发主控 | 悲观行锁 `SELECT ... FOR UPDATE` |
| 幂等第一层 | 进入时先查 `(biz_type, biz_no)` 流水，命中直接返回 |
| 幂等第二层 | 插入流水时 `uk_txn_biz` 唯一索引兜底（冲突转幂等命中） |
| 幂等第三层 | 业务单状态机（充值单 PAID） |
| 乐观锁 | `@Version` + `OptimisticLockerInnerInterceptor`（最后防线） |
| 扣款顺序 | GIFT_FIRST，**禁止按比例分摊** |
| 退款 | 按原资金构成回冲（principalPart 向下取整，giftPart 减法兜底） |

## 3. 跨服务接口

### 3.1 wallet-service 新增

```text
POST /api/wallet/internal/recharge-in          充值入账
POST /api/wallet/internal/consume-out          消费扣款
POST /api/wallet/internal/refund-in            退款回冲
POST /api/wallet/internal/recharge-refund-out  充值退款
POST /api/wallet/internal/adjust               人工调整
GET  /api/wallet/internal/balance              查询余额
```

全部受 `X-Internal-Token` 保护（无令牌 / 错令牌 → 401 + `code=10402`）。

### 3.2 auth-service 新增

```text
GET /api/auth/internal/brand/{brandId}/deduct-order   品牌扣款顺序
GET /api/auth/internal/brand/{brandId}                品牌基础信息
```

### 3.3 Feign 跨服务调用实测

```text
1. 不传 deductOrder 调 wallet 扣款接口
2. wallet-service 通过 Feign 调 auth-service 获取品牌配置
3. auth-service 日志：查询品牌扣款顺序: brandId=1 order=GIFT_FIRST
   traceId=0fba391519ee41fc（与调用方一致）
4. Redis 缓存写入：tc:brand:1:deduct-order = "GIFT_FIRST"，TTL 49 秒
5. 扣款结果：赠送扣=-500 实付扣=0 → 正确按 GIFT_FIRST 先扣赠送金
```

## 4. 本轮修复的问题

| # | 问题 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 迁移脚本跨实例 `INSERT...SELECT` 失败 | 3306 与 3307 是不同实例 | 改用 `mysqldump \| mysql` 管道 |
| 2 | 校验器 `oms_order.pay_amount` 列不存在 | 实际列名为 `paid_amount` | 按真实列名修正 |
| 3 | 校验器 I6 误报 1 处断裂 | 用了所有配对而非相邻配对 | 改用 `LAG()` 取相邻流水 |
| 4 | 校验器 `out_trade_no` 列不存在 | 实际列名为 `payment_no` | 修正并增加微信交易号校验 |
| 5 | 订单明细 `item_amount/qty` 列不存在 | 实际为 `total_amount/quantity` | 修正并增加名称规格快照校验 |
| 6 | Mapper 未注册 | `@MapperScan` 替换未生效（原文格式不同） | 正确写入启动类 |
| 7 | `Property 'sqlSessionFactory' is required` | 骨架测试排除了 DataSourceAutoConfiguration | 移除排除，6 个服务统一修正 |
| 8 | `CacheService` Bean 缺失 | common-redis 的 `@Service` 类不在扫描范围 | 改为自动配置里显式 `@Bean` |
| 9 | `Column 'create_time' cannot be null` | `@TableField(fill=INSERT)` 需 MetaObjectHandler | 迁移 `MyMetaObjectHandler` 到 common-core |
| 10 | 品牌接口 500 | `sys_brand` 主键列是 `id` 不是 `brand_id` | 修正 SQL |
| 11 | 清理测试数据破坏不变量 | 直接 DELETE 流水未回滚余额 | 加 `--force` 参数可重做迁移；测试用会员 ID ≥ 900000 隔离 |

> **第 11 项是本轮的重要教训**：资金数据不能手工删除。
> 测试数据必须用独立会员 ID 隔离，且清理后必须复核不变量。
