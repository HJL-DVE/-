## 1. 接口总约定

### 1.1 URL 规范

```
管理端：  /api/admin/{模块}/{资源}[/{id}]
会员端：  /api/app/{模块}/{资源}[/{id}]
支付回调：/api/payment/notify/{provider}     （无鉴权，靠验签）
开放文档：/swagger-ui.html  与  /v3/api-docs
健康检查：/actuator/health
```

| 模块段 | 含义 |
| --- | --- |
| `auth` | 认证与令牌 |
| `system` | 用户、角色、权限、配置、日志 |
| `store` | 品牌、门店 |
| `member` | 会员、等级、标签 |
| `product` | 分类、商品、SKU、门店商品、库存 |
| `wallet` | 钱包、流水、充值方案、充值订单 |
| `order` | 订单 |
| `payment` | 支付单、退款单、通知 |
| `marketing` | 优惠券、活动、积分、签到 |
| `report` | 统计报表 |

### 1.2 方法语义

| 方法 | 用途 | 幂等 |
| --- | --- | --- |
| GET | 查询 | 天然幂等 |
| POST | 创建 / 执行动作（支付、退款、核销） | 通过 `Idempotency-Key` 保证 |
| PUT | 全量更新 | 幂等 |
| PATCH | 部分更新 / 状态流转 | 幂等 |
| DELETE | 逻辑删除 | 幂等 |

### 1.3 统一响应格式

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "traceId": "9f2c1a3b",
  "timestamp": "2026-01-01T10:00:00+08:00"
}
```

分页响应 `data` 结构：

```json
{
  "records": [],
  "total": 128,
  "pageNo": 1,
  "pageSize": 20,
  "totalPages": 7
}
```

### 1.4 错误码规范

错误码为 5 位数字：`前2位模块 + 后3位序号`。

| 区间 | 模块 | 示例 |
| --- | --- | --- |
| `00000` | 成功 | `0` |
| `100xx` | 通用/参数 | `10001` 参数校验失败 |
| `101xx` | 认证 | `10101` 未登录、`10102` 令牌过期、`10103` 密码错误 |
| `102xx` | 授权 | `10201` 无功能权限、`10202` 无门店数据权限 |
| `200xx` | 系统管理 | |
| `300xx` | 门店 | |
| `400xx` | 会员 | |
| `500xx` | 商品 | |
| `600xx` | 储值与钱包 | `60101` 余额不足、`60102` 钱包冻结、`60103` 跨店禁用 |
| `700xx` | 订单 | `70101` 订单状态不允许该操作 |
| `800xx` | 支付 | `80101` 支付单不存在、`80102` 验签失败、`80103` 金额不符 |
| `900xx` | 营销 | `90101` 券不可用、`90102` 积分不足 |
| `50000` | 系统异常 | 兜底 |

### 1.5 分页与排序参数

```
pageNo    int     默认 1，最小 1
pageSize  int     默认 20，最大 100
sortBy    string  排序字段（白名单校验，防止 SQL 注入）
sortOrder string  asc | desc
```

### 1.6 金额传输约定

- 所有金额字段在 JSON 中为 **整数**（单位：分），类型 `Long`。
- 字段名以 `Amount` 或 `Balance` 结尾，前端据此格式化。
- **禁止**传输 `"99.90"` 这类字符串金额。

请求：

```json
POST /api/admin/order/orders
Headers: Authorization: Bearer xxx, Idempotency-Key: pos-20260101-0001

```

  Wechatpay-Timestamp: ...

  Wechatpay-Serial: ...

## 5. 安全设计

### 5.1 密码与凭据

| 项 | 方案 |
| --- | --- |
| 密码存储 | BCrypt（strength=10） |
| 密码策略 | 8–32 位，需含字母与数字 |
| 登录失败锁定 | 连续 5 次失败锁定 15 分钟，计数落库 |
| 初始密码 | 演示账号 `TeaClub@123`，生产环境首次登录强制改密 |

### 5.2 JWT 设计

```json
{
  "sub": "1",
  "aud": "admin",
  "jti": "uuid",
  "uid": 1,
  "brandId": 1,
  "roles": ["STORE_MANAGER"],
  "stores": [1],
  "iat": 1735700000,
  "exp": 1735707200
}
```

- 管理端 `aud=admin`，会员端 `aud=member`，**使用不同签名密钥**。
- 令牌只携带标识，**权限点在服务端实时加载**（避免权限变更后令牌仍有效）。
- 登出/改密时将 `jti` 写入 Redis 吊销名单，有效期与令牌一致。

### 5.3 敏感数据保护

| 数据 | 保护措施 |
| --- | --- |
| 会员手机号 | 列表接口脱敏 `138****0001`；详情接口按权限返回明文 |
| 密码 | 任何接口与日志均不返回、不打印 |
| 微信 APIv3 密钥 / 私钥 | 仅环境变量；日志打印时强制 `***` |
| 支付通知报文 | 存储前脱敏，不含密钥 |
| 操作日志入参 | 过滤 `password`、`privateKey`、`apiV3Key` 等字段 |

### 5.4 传输与其他

- 生产环境强制 HTTPS（Nginx 终止 TLS）。
- 全部接口配置 CORS 白名单，不使用 `*`。
- 限流：登录接口按 IP + 账号维度限流（Redis 或本地令牌桶）。
- SQL 注入：全部使用 MyBatis 参数占位；排序字段走白名单校验。
- XSS：富文本字段入库前过滤；前端渲染使用文本插值。
- 越权：见《04》§8。

### 5.5 密钥注入规范

```yaml
# application.yml 只允许出现占位符
teaclub:
  payment:
    provider: ${TEACLUB_PAYMENT_PROVIDER:mock}
    wechat:
      merchant-id: ${WXPAY_MCH_ID:}
      merchant-serial-no: ${WXPAY_MCH_SERIAL:}
      api-v3-key: ${WXPAY_API_V3_KEY:}
      private-key-path: ${WXPAY_PRIVATE_KEY_PATH:}
      app-id: ${WXPAY_APP_ID:}
      notify-url: ${WXPAY_NOTIFY_URL:}
```

- 仓库中 **不得** 出现真实密钥、证书文件、商户号。
- 提供 `.env.example` 说明变量含义，`.env` 加入 `.gitignore`。
