1. 项目背景

  • 行业痛点：连锁奶茶店会员分散、储值资金管理不规范、营销活动效果难度量
  • 解决思路：统一的会员储值营销平台，总部集中运营、门店按权限使用
  • 课程目标：实践微服务拆分、分布式事务（Outbox/Saga）、消息可靠投递、资金一致性设计

客户端 Gateway :9000 (JWT/路由/白名单) ├─ Vue3 管理后台 :8080 │ └─ 微信小程序 │ lb:// 按服务名路由 ┌─────────┼─────────┐ ▼ ▼ ▼ ▼ ▼ auth member product wallet order payment marketing report :9001 :9002 :9003 :9004 :9005 :9006 :9007 :9008 iam_db member_db product_db wallet_db order_db payment_db marketing_db report_db │ (独立库 + 独立账号 tc_xxx) Nacos 注册/配置 RabbitMQ 事件 Redis 缓存

服务间通信

  • 同步 OpenFeign：订单→商品（价格）、订单→钱包（扣款）、订单→营销（券试算）
  • 异步 RabbitMQ：ORDER_PAID → 会员档案+积分+活动；REFUND_SUCCEEDED → 积分冲正
  • 报表跨库只读：SELECT-only 账号聚合，不侵入业务服务

7. 会员储值与钱包

双账本设计

  • 本金 principal_balance：真实收款
  • 赠送 gift_balance：营销赠送
  • 充 100 送 20 → 到账 120，收款只认 100
  • 赠送可设有效期，批次过期任务扣减

资金安全四道防线

  • ① 条件 UPDATE 防超扣
  • ② 唯一索引 防重复入账
  • ③ 链式流水 逐笔审计
  • ④ 冻结模型 下单预占

充值流程

创建充值单 → 创建支付单(PAYING) → Mock 回调（验签/金额校验） → 支付单 SUCCESS → 充值单 PAID → 钱包本金+赠送入账 → 链式流水记录

✓ 实测重复回调余额不变（幂等）

8. 订单与 Mock 支付

订单金额：全部服务端计算

商品总额 → 活动折扣 → 等级折扣(9.5折) → 券抵扣(满50减10) → 应付金额

  • 前端只传商品和数量，金额不可篡改
  • 优惠券抵扣由 marketing-service 试算判定
  • 下单锁券(UNUSED→LOCKED) → 支付核销(→USED) → 取消释放

Mock 支付

  • provider=mock 条件装配，保留验签、幂等、状态机真实逻辑
  • notify 校验签名+金额，不符拒绝；已 SUCCESS 拒绝二次变更
  • 重复回调实测不重复入账
  • 前端明确标注「模拟支付数据，非真实收款」

9. 会员营销体系

优惠券

  • 模板 8 类 / 范围(门店商品等级)
  • 领取：Redis 锁 + 限领
  • 状态机：UNUSED→LOCKED→USED
  • 抵扣由营销服务试算判定

积分

  • 消费得分（等级倍率实算）
  • 签到 / 活动奖励 / 商城兑换
  • 退款按原流水冲正
  • 批次有效期管理

会员等级（自动升级）

  • 5 级：普通→银卡→金卡→黑金→钻石
  • 门槛：0/500/1500/5000/12000 元
  • 消费后自动重算（只升不降）
  • 权益：倍率/折扣/生日礼

营销活动（8 类）

  • 满赠/门店活动：事件自动触发
  • 参与记录唯一键防重
  • 发奖 REQUIRES_NEW 独立事务

11. 经营报表

9 页可视化（ECharts）

总部驾驶舱门店驾驶舱销售分析 商品分析会员分析充值统计 支付统计退款统计营销分析

严格口径

  • 销售 = 订单实付（PAID/COMPLETED/REFUNDING/REFUNDED）

  • 钱包消费：单列展示，不混入支付收款

实现

  • report-service 跨库 SELECT-only 聚合（独立账号 tc_report）
  • 11 个 GET 接口，支持日期 + 门店筛选，趋势补零
  • 权限：总部全量 / 店长本店（越权 10202）/ 收银员拒绝（10201）

14. 项目总结

技术收获

  • 微服务拆分实战：业务域边界、独立库、服务通信选型
  • 分布式事务：Outbox 原子事件、Saga 补偿、REQUIRES_NEW 隔离
  • 消息可靠性：DLQ + 定时补偿重放，失败不丢消息
  • 资金一致性：双账本、条件 UPDATE、链式流水、幂等三层
  • 真实问题排查：缓存污染、幂等键隔离、事务传播等 8+ 缺陷定位修复

工程规范

  • 19 个自动化脚本纳入回归门禁，246 断言守护
  • 20+ 篇文档与代码同步演进
  • Git 提交 40+ 次，每次提交对应可验证的功能
