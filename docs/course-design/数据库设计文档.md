# TeaClub 数据库设计文档

> 本文档按**实际数据库结构**生成（直接从运行中的 MySQL 导出字段与索引），无编造内容。
> 共 8 个数据库、63 张表（含各服务 Outbox/Inbox 通用表），此处收录 20 张核心业务表。

---

## 一、数据库清单

| 数据库 | 所属服务 | 表数 | 说明 |
| --- | --- | --- | --- |
| iam_db | auth-service | 13 | 用户/角色/权限/门店/品牌/操作日志/Outbox-Inbox |
| member_db | member-service | 7 | 会员/等级/微信绑定/标签/Outbox-Inbox |
| product_db | product-service | 8 | 分类/SPU/SKU/库存/门店商品/Outbox-Inbox |
| wallet_db | wallet-service | 8 | 钱包/流水/冻结/充值订单/套餐/Outbox-Inbox |
| order_db | order-service | 6 | 订单/明细/状态日志/Saga/Outbox-Inbox |
| payment_db | payment-service | 5 | 支付单/退款单/回调日志/Outbox-Inbox |
| marketing_db | marketing-service | 21 | 券模板/券/流水/积分账户/流水/批次/活动/权益/签到/商城 |
| report_db | report-service | 0 | 跨库只读聚合，无本地表 |

每个库使用独立账号（tc_auth / tc_member / tc_product / tc_wallet / tc_order / tc_payment / tc_marketing / tc_report），服务间禁止跨库写；report 使用跨库 SELECT-only 账号。

---

## 二、表间关系总览

- **权限体系**：sys_user ←sys_user_role→ sys_role ←sys_role_permission→ sys_permission（树形，parent_id）；sys_user ←sys_user_store→ sys_store（店长绑定门店，控制数据范围）；
- **会员**：mem_member.level_id → mem_member_level（多对一）；mem_member ←mem_member_wx（openid 绑定）；mem_member = wal_wallet（1:1 钱包）；
- **商品**：prd_category ← prd_spu ← prd_sku（1:N）；prd_spu ← prd_store_spu / prd_store_sku（门店商品定价上架）；
- **交易**：mem_member = oms_order.member_id；oms_order 1→N oms_order_item；oms_order 1→1 pay_payment_order（经 biz_no 关联）1→N pay_refund_order；
- **钱包**：wal_wallet 1→N wal_wallet_transaction（链式流水）1→N wal_wallet_freeze；wal_recharge_plan 1→N wal_recharge_order；
- **营销**：mkt_coupon_template 1→N mkt_coupon（领取）；mkt_coupon_template 1→N template_store/spu/level（范围）；mem_member 1→N mkt_points_account 1→N transaction/batch；mkt_activity 1→N activity_record。

## 四、通用表（每库同名）

sys_outbox_message / sys_inbox_message —— Outbox-Inbox 可靠消息模式：业务与事件同事务写 Outbox，Relay 定时投递 MQ；消费端先写 Inbox（与业务同事务）实现幂等。

sys_idempotency_record（iam_db）—— 接口幂等记录。
