## 5. 构建方案演进（关键经验）

### 5.1 为什么不用容器内 Maven 构建

初版 Dockerfile 在容器内跑 `mvn package`，每次都要重新下载依赖，
实测超过 2 分钟仍未产出镜像，且因超时中断。

**改为**：宿主机构建 jar → 轻量镜像 COPY。

```text
宿主机 mvn -pl <module> -am clean package     → 7~15 秒（复用 1.58GB .m2 缓存）
docker build（仅 COPY jar）                    → 10~14 秒
7 个服务全部镜像                               → 14.2 秒
```

### 5.2 Dockerfile 最终形态

```text
FROM eclipse-temurin:17-jre-jammy
WORKDIR /app
ENV JAVA_OPTS="-Xms256m -Xmx512m -XX:+UseG1GC -Duser.timezone=Asia/Shanghai"
RUN groupadd -r teaclub && useradd -r -g teaclub teaclub
COPY target/*.jar /app/app.jar
RUN chown -R teaclub:teaclub /app
USER teaclub
ENTRYPOINT ["sh", "-c", "exec java $JAVA_OPTS -jar /app/app.jar"]
```

构建上下文 = 模块目录（含 target/*.jar）。

> 注意：`.dockerignore` **不能**排除 `target/`，否则 COPY 找不到 jar。

## 6. 本轮修复的问题（完整记录）

| # | 问题 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | Nacos 容器反复重启（4 轮） | 镜像内 `application.properties` 的 `db.url.0` 含 `${MYSQL_SERVICE_HOST}` 占位符 | 从镜像提取原始配置，精确改 4 行为内嵌 Derby |
| 2 | 依赖下载超时，镜像构建失败 | 容器内 Maven 需重下全部依赖 | 改宿主机构建 + 轻量镜像 |
| 3 | `COPY report-service` not found | 构建上下文是子模块，缺父 pom | 上下文改为 `teaclub-cloud`，后改为模块目录 |
| 4 | `build.volumes` 非法 | compose build 块不支持 volumes | 改用 `additional_contexts`（后改宿主机构建，不再需要） |
| 5 | `COPY target/*.jar` 找不到 | `.dockerignore` 排除了 target | 修正 .dockerignore |
| 6 | gateway 容器启动失败 | 缺 `spring.config.import=nacos:...` | docker profile 补 config.import + import-check.enabled=false |
| 7 | 客户端持续报 `User nacos not found` | Nacos 关了认证，客户端仍带 username/password | 移除客户端认证参数 |
| 8 | dev-token 端点 404 | `DEV_TOKEN_ENDPOINT` 未进 `common-env` | 加入 common-env 锚点 |
| 9 | token 端点 500 | `application-docker.yml` 缺 `teaclub.jwt` 配置 | docker profile 补 jwt 段 |
| 10 | 业务服务无端口映射 | compose 未声明 ports | 补充 9001~9006 映射 |

## 8. 启动与停止

```bash
cd deploy

# 启动（首次会构建镜像）
docker compose -f docker-compose.yml --env-file .env.docker up -d --build

# 查看状态
docker compose -f docker-compose.yml --env-file .env.docker ps

# 查看日志
docker logs teaclub-gateway -f

# 停止
docker compose -f docker-compose.yml --env-file .env.docker down

# 停止并清空数据
docker compose -f docker-compose.yml --env-file .env.docker down -v
```

## 9. 与本机原生环境的关系

容器端口全部错开（3307/6380），与本机单体项目（3306/6379）并存互不干扰。

Nacos 与 RabbitMQ 的端口（8848/5672）与原生版相同，**容器化部署时需先停原生版**：

```bash
# 停原生 Nacos
H:/deepseek/_downloads/nacos/nacos/bin/shutdown.cmd
# 停原生 RabbitMQ
cd H:/deepseek/_downloads/rabbitmq/rabbitmq_server-3.13.7/sbin && rabbitmqctl stop
```

## 10. 安全说明

- `deploy/.env.docker` 含数据库密码、JWT 密钥、内部调用凭证，**已被 .gitignore 忽略**
- 容器内应用以**非 root** 用户（teaclub）运行
- 各服务只被授权访问自己的数据库，跨库访问由 MySQL 拒绝
- `DEV_TOKEN_ENDPOINT=true` 仅用于开发联调，**生产环境必须移除**
