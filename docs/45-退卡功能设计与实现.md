## 1. 业务口径（回答「充 100 送 20 退多少」）

**退 100 元现金，20 元赠送全额扣回；赠送金不折现，绝不退 120。**

| 项 | 处理 |
| --- | --- |
| 实付本金 100 元 | 按原支付渠道**原路退回**（微信支付单的 `refund_cash_amount`） |
| 赠送金 20 元 | 记 `RECHARGE_REFUND_OUT` 流水，从 `gift_balance` **扣回**，不产生现金 |
| 退款单 `refund_amount` | = 实付本金 100 元；赠送金不计入退款金额 |
| 报表口径 | 退款金额计 100 元；充值额/赠送额仍按原充值单归集，不重复计收 |

依据：`docs/04` §2.3 场景 C、§3 退款矩阵（`赠送金不折现`）、`docs/03` §7 统计口径冻结。

## 2. 接口

```text
POST /api/admin/payment/recharge-refunds
权限：wallet:refund（SUPER_ADMIN / HQ_ADMIN）
请求：{ "rechargeNo": "RC...", "reason": "顾客退卡" }   ← 不接受任何金额字段
响应：RefundVO（refundNo / refundAmount / refundCashAmount / status ...）
```

金额全部由服务端按充值单计算，调用方只提供单号——与下单、支付「不信任客户端金额」的约定一致。

---

## 3. 执行流程

```text
管理端「退卡」
   │
   ├─ ① payment-service 读充值单（Feign → wallet-service）
   │     校验：存在 / 品牌归属 / 门店数据权限 / status=PAID / 有成功支付单 / 未退过
   │     计算：principal = recharge_amount，gift = gift_amount
   │
   ├─ ② 建退款单 pay_refund_order（biz_type=RECHARGE, biz_no=充值单号）
   │     refund_amount = refund_cash_amount = principal；refund_gift_amount = 0
   │
   ├─ ③ 先扣回钱包（Feign → wallet-service /recharge-refund-out）
   │     余额不足 → 抛错 → 本地退款单回滚（绝不「钱退了、储值还在」）
   │
   ├─ ④ 渠道原路退款（provider.createRefund）
   │     受理失败 → 调 /adjust 回补钱包（幂等键 UNDO-<退款单号>）→ 退款单 FAILED
   │     SUCCESS    → 退款单 SUCCESS + 充值单置 REFUNDED
   │     PROCESSING → 退款单 PROCESSING，等退款通知
   │
   └─ ⑤ Mock 环境需再调一次 POST /api/payment/mock/refund-notify {refundNo}
         → handleRefundSuccess 的 RECHARGE 分支推进充值单 REFUNDED
```

「先扣回、后退款」是刻意选择的顺序：钱包的余额校验（行锁 + 唯一索引）会在赠送金已被消费时直接拒绝，
把风险挡在现金流出之前。

---

## 4. 幂等与一致性

| 层次 | 机制 |
| --- | --- |
| 重复点击 | `selectActiveByBizForUpdate('RECHARGE', rechargeNo)`（FOR UPDATE 间隙锁）命中有效退款单直接返回原单 |
| 并发建单 | 同一充值单的间隙锁 + `uk_refund_no`；第二笔请求拿不到锁/命中幂等 |
| 钱包扣回 | `uk_txn_biz('RECHARGE_REFUND_OUT', refundNo)` 唯一索引兜底 |
| 充值单终态 | `markRechargeRefunded` 强制校验扣回流水存在，否则拒绝改状态（防账实不符） |
| 失败可重试 | FAILED/CANCELLED 的退款单不计入幂等；重试生成新 refundNo，钱包按新键重新扣回 |
| 渠道失败补偿 | `/adjust` 以 `UNDO-<退款单号>` 为幂等键把扣回金额原样加回，并留 ADMIN_ADJUST 流水 |

---

## 5. 边界行为（如实）

| 场景 | 系统行为 |
| --- | --- |
| 顾客已消费、赠送金不足 20 | wallet 余额校验失败 → 退卡被拒，提示「余额不足，无法扣回充值金额」，需人工部分退款/调整 |
| 充值单未支付 / 已取消 | 拒绝退卡（仅 status=PAID 可退） |
| 支付单非 SUCCESS | 拒绝退卡（无原路可退） |
| 已退过（其他退款单占用） | 拒绝重复退卡 |
| Mock 渠道退款 | `createRefund` 返回 PROCESSING，需显式模拟退款通知才到 SUCCESS；真实微信渠道按通知/查单确认 |
