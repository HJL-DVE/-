## 二、并发安全实现说明

三层保护，缺一不可：

```text
第一层  SELECT ... FOR UPDATE      行锁串行化同一钱包的余额变更
第二层  version 乐观锁              MyBatis-Plus @Version，防跨事务丢失更新
第三层  uk_txn_biz 唯一索引         数据库级幂等，网络重试也只入账一次
```

> Redis 分布式锁存在于 common-redis，但**不作为资金一致性的唯一保障** ——
> 它只是性能优化，正确性由上述三层数据库机制保证。

## 四、冻结设计要点（避免破坏不变量）

规格明确要求「不能直接修改余额模拟冻结」。本项目冻结实现：

```text
冻结    -> 只写 wal_wallet_freeze 记录（status=FROZEN），余额不动，不写流水
确认扣款 -> 标记 CONFIRMED + 走 consumeOutExact 写流水并真扣余额
释放    -> 只把状态改 RELEASED，余额不变，不写流水
```

因为「冻结期间余额未变」，所以 `余额 = 流水累计` 这条核心不变量在任何时刻都成立。
