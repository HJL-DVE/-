## 4. Nacos 容器启动问题（踩坑记录）

Nacos 容器反复重启（Restarting，退出码 1），共排查 4 轮才定位：

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | `UnknownHostException: ${MYSQL_SERVICE_HOST}` | 镜像内 `application.properties` 的 `db.url.0` 含该占位符；传 `SPRING_DATASOURCE_PLATFORM` 会触发 MySQL 分支 | 去掉该环境变量 |
| 2 | `Connection refused`（仍走 MySQL） | 变量**置空也算"存在"**，startup.sh 仍切 MySQL 模式 | 完全不声明该变量 |
| 3 | `Driver com.mysql.cj.jdbc.Driver claims to not accept jdbcUrl, jdbc:derby:...` | 挂载的精简配置里 `db.url.0` 是 Derby，但驱动判定仍走 MySQL | 改为**完整覆盖**原文件 |
| 4 | 最终解 | 从镜像中提取**原始** `application.properties`（53 行），只精确修改 4 行：`spring.sql.init.platform` 置空、`db.url.0` 改 Derby、`db.user.0`/`db.password.0` 固定 | ✅ healthy |

**最终方案**：`deploy/nacos/conf/application.properties`（从镜像提取后精确修改）挂载到容器。

## 5. 镜像构建

每个服务一个 Dockerfile（`teaclub-cloud/<module>/Dockerfile`），多阶段构建：

```text
阶段 1: maven:3.9.6-eclipse-temurin-17 —— mvn -pl <module> -am clean package
阶段 2: eclipse-temurin:17-jre-jammy   —— 非 root 运行
```

**构建上下文必须是 `teaclub-cloud`**（需要父 pom.xml 与所有模块）。
最初把 Dockerfile 放在子模块目录、以子模块为上下文，导致
`COPY report-service ./report-service` 失败（"/report-service": not found）。

compose 中每个服务的 build 段：

```yaml
build:
  context: ../teaclub-cloud
  dockerfile: gateway-service/Dockerfile
  args:
    SERVICE_BUILD: gateway-service
```

## 8. 与本机原生环境的并存关系

```text
容器环境（新增）              本机原生环境（保留）
MySQL    3307                MySQL    3306   单体项目用
Redis    6380                Redis    6379   单体项目用
Nacos    8848                Nacos    8848   ⚠️ 端口冲突，需停原生版
RabbitMQ 5672                RabbitMQ 5672   ⚠️ 端口冲突，需停原生版
```

**注意**：重启后本机原生版 Nacos（8848）与 RabbitMQ（5672）也启动了，
与容器端口冲突。容器化部署时需先停止原生版：

```bash
# 停止原生 Nacos
H:/deepseek/_downloads/nacos/nacos/bin/shutdown.cmd
# 停止原生 RabbitMQ
# 在其 sbin 目录执行 rabbitmqctl stop
```
