## 一、背景：原本一张图都没有

排查发现数据库里的图片字段**全部为 NULL**：

| 表 | 字段 | 修复前 |
| --- | --- | --- |
| `prd_spu` | `main_image`（注意：不是 `image_url`） | 全 NULL |
| `prd_sku` | `image_url` | 全 NULL |
| `prd_category` | `icon_url` | 全 NULL |
| `iam_db.sys_brand` | `logo_url` | NULL |

所以小程序页面缺图**不是渲染问题，是本来就没有图片数据**。
后端映射本身是正确的：`ProductAppController` 里 `spu.getMainImage()` → `AppSpuItemVO.imageUrl`。

## 二、修复后的存储方式

图片文件放在两处（由各自的构建工具原样复制到产物）：

```text
frontend/teaclub-miniprogram/src/static/images/   <- uni-app 打包时复制到 dist/build/mp-weixin/static
frontend/teaclub-admin/public/static/images/      <- Vite 复制到 dist/static，由 nginx 静态提供
```

数据库里存**相对路径**，不存域名：

```sql
-- 分类
UPDATE prd_category SET icon_url = CONCAT('/static/images/category/', id, '.jpg') WHERE id IN (1,2,3,4);
-- 商品（真实列名是 main_image）
UPDATE prd_spu SET main_image = CONCAT('/static/images/spu/', id, '.jpg') WHERE id IN (1,2,3,4,5,6,22);
-- SKU 继承所属商品主图
UPDATE prd_sku s JOIN prd_spu p ON p.id = s.spu_id SET s.image_url = p.main_image WHERE s.image_url IS NULL;
```

> 存相对路径的原因：小程序 `<image src>` 支持 `/` 开头的**包内绝对路径**，
> 直接读包内文件，不需要拼接网关地址、不走网络请求、不受 downloadFile 白名单限制。
> 若拼成 `http://...` 反而会变成跨域网络请求，小程序还要额外配置合法域名。

## 四、前端兜底逻辑

`frontend/teaclub-miniprogram/src/utils/normalize.ts`：

```ts
function resolveImage(raw) {
  const v = (raw || '').trim()
  if (!v) return ''
  if (v.startsWith('http://') || v.startsWith('https://') || v.startsWith('/')) return v
  return '/static/images/' + v
}
```

- `spuImage(spu)` / `categoryIcon(cat)` 统一走它
- 完全没图时：商品不渲染 `<image>`；分类退化为**分类名首字**占位块
- 管理后台：新增「图片」列，`el-image` 支持点击预览、加载失败显示"无图"

## 六、注意

1. **图片是本地静态资源，不是 CDN**。上线后如需换 CDN，只需批量改库里字段为完整 URL，前端 `resolveImage` 已支持以 `http` 开头直接返回。
2. **`prd_spu` 的列名是 `main_image` 而不是 `image_url`** —— 写 SQL 或加新接口时容易踩，这里显式记录。
3. 新增商品后如果没有配图，前端会自动走"无图"兜底，不会白屏。
