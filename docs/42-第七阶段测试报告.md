## 三、专项设计要点

### 3.1 失败注入（脚本 24）

用 `RENAME TABLE mem_member TO mem_member_bak` 让消费必然失败，
验证「失败→DLQ→恢复→重放→成功」全链路后恢复表名。**不 mock、不造假数据**。

### 3.2 重复投递（脚本 22）

从 sys_outbox_message 取原始 event_id，直接重发同一事件到交换机，
断言积分余额不变、ORDER_EARN 流水仍为 1 条。

### 3.3 并发与幂等

- 领券 800ms Redis 锁 + DB 限领计数 + 流水唯一键三层
- 活动名额条件 UPDATE（used_quota < total_quota）
- 商城库存条件 UPDATE（stock >= qty 或 -1 不限）
- 积分扣减条件 UPDATE（total_points >= cost）
