## 二、#1 支付超时关单

### 实现

```text
PaymentTimeoutCloser（每 60 秒）
  扫描 status IN ('CREATED','PAYING') AND create_time < NOW() - 30min
  -> 加行锁复核状态（防止与成功通知竞争）
  -> 调渠道 provider.closeOrder()（失败不阻断本地关单）
  -> status = CLOSED，fail_reason 记录原因
```

### 为什么不会误关已支付的单

```text
1. 只扫 CREATED/PAYING，SUCCESS/FAILED/CLOSED 都是终态不会被选中
2. 关单前 selectByNoForUpdate 加行锁，再复核一次状态
   若期间已被成功通知推进 -> 直接跳过，绝不关单
3. 关单只改支付单，不动订单与钱包 —— 订单仍 UNPAID，用户可重新支付
```

### 实测

```text
创建支付单 -> 状态 PAYING
把 create_time 改为 120 分钟前
等待关单任务...
-> 支付单状态 CLOSED
-> 对应订单状态仍为 UNPAID（未被误改）
```

配置项：`teaclub.payment.timeout-minutes`（默认 30）、`timeout-scan-ms`（默认 60000）、`timeout-close-enabled`。

## 三、#2 Outbox 接入真实业务流

此前 Outbox 只有演示端点。现在业务方法内直接登记事件，
「业务数据 + 事件」在同一个本地事务提交，由 Relay 异步投递。

| 服务 | 触发点 | 事件 |
| --- | --- | --- |
| order-service | 余额支付成功 | `ORDER_PAID` |
| order-service | 微信支付回写订单已支付（内部接口） | `ORDER_PAID` |
| wallet-service | 充值入账 | `RECHARGE_PAID` |
| wallet-service | 消费扣款 | `WALLET_DEDUCTED` |
| wallet-service | 冻结余额 | `WALLET_FROZEN` |
| wallet-service | 冻结确认扣款 | `WALLET_DEDUCTED`（source=freeze-confirm） |
| payment-service | 支付成功 | `PAYMENT_SUCCEEDED` |
| payment-service | 退款成功 | `REFUND_SUCCEEDED` |

### 实测（各库 outbox 表，状态均为 SENT）

```text
order_db    ORDER_PAID            SENT  2
wallet_db   RECHARGE_PAID         SENT  1
            WALLET_DEDUCTED       SENT  2
            WALLET_FROZEN         SENT  1
payment_db  PAYMENT_SUCCEEDED     SENT
            REFUND_SUCCEEDED      SENT
```

说明：事件由各服务**自己的** outbox 表承载（与业务库同库同事务），
Relay 投递到 RabbitMQ 后标记 SENT，消费端以 `event_id` 幂等去重。

## 四、#3 订单-钱包跨服务对账

### 为什么需要它

wallet-service 的对账只回答「库内是否自洽」（余额 = 流水累计）。
但它无法回答：**一张标记为余额已支付的订单，钱包里到底有没有对应扣款流水？**

### 实现

```text
OrderWalletReconciliationService（每 15 分钟）
  取最近 7 天 pay_channel='BALANCE' 且状态 PAID/COMPLETED/REFUNDING/REFUNDED 的订单
  -> 逐笔调 wallet-service GET /txn-exists?bizType=CONSUME_OUT&bizNo={订单号}
  -> 不存在 => 记为不一致 ORDER_PAID_WITHOUT_WALLET_TXN
  -> 调用失败 => 计入 unknown，不误判为不一致
```

### 实测

```text
POST/GET /api/order/internal/reconcile?days=7
-> checked=7  unknown=0  issues=0  passed=true
```

## 五、#4 冻结部分确认

### 语义

```text
冻结 3000 实付 / 1000 赠送
部分确认 1200 / 300
  -> 只扣 1200 / 300，写资金流水
  -> 剩余 1800 / 700 视为释放（随记录状态变更）
  -> 冻结记录 status=CONFIRMED，金额改为实际扣除额，remark 记录释放量
```

### 实测

```text
充值 10000/5000
冻结 3000/1000          -> 可用 7000/4000
部分确认扣 1200/300     -> 实付变动 -1200，赠送变动 -300
                        -> 可用 8800/4700（余额 8800/4700）
                        => 剩余 1800/700 已释放
```

### 校验规则

| 校验 | 行为 |
| --- | --- |
| 确认额 > 冻结额 | 拒绝 |
| 确认额为负 | 拒绝 |
| 确认额为 0 | 拒绝（提示改用释放冻结） |
| 记录已 CONFIRMED | 幂等返回原流水 |
| 记录非 FROZEN | 拒绝 |
