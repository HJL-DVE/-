## 2. 环境准备方案

```powershell
# 统一入口（写入所有 scripts/*.ps1）
$MvnCmd = 'C:\Users\Admin\apache-maven-3.9.6\bin\mvn.cmd'

$MvnWrapper = Join-Path $PSScriptRoot '..\backend\mvnw.cmd'
```

## 3. MySQL 处理路径（解决 P4）

按优先级尝试，**任一步成功即停止**。

> **✅ 状态：已解决。** 采用路径 A，root 密码可用。已创建项目专用账号 `teaclub`@`localhost` 与 `teaclub`@`127.0.0.1`，仅授予 `teaclub.*` 权限（无全局权限），并已通过写库探针验证。
> 初始化脚本保留在 `scripts/init-teaclub-db.sql`，供他人复现环境。

### 路径 A：使用已有密码（推荐）

```powershell
$env:MYSQL_PWD='<用户提供的密码>'
& 'C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe' -u root -e "SELECT VERSION();"
```

成功后创建项目专用账号（避免使用 root）：

```sql
CREATE DATABASE IF NOT EXISTS teaclub DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'teaclub'@'localhost' IDENTIFIED BY '<随机强密码>';
GRANT ALL PRIVILEGES ON teaclub.* TO 'teaclub'@'localhost';
FLUSH PRIVILEGES;
```

> 密码写入 `.env`（已被 `.gitignore` 忽略），不提交仓库。

### 路径 B：临时以 skip-grant-tables 重置 root 密码

> ⚠ **此操作会导致本机 MySQL 短暂不可用，属于需要用户明确批准的类别。**

1. `Stop-Service MySQL84`
2. 以 `--skip-grant-tables --skip-networking` 启动 mysqld
3. 连接并重置 root 密码
4. 恢复正常启动
5. 验证连接

### 路径 C：使用独立实例（零侵入，本机推荐）

- 在另一端口（如 3307）以 `--datadir` 指向新目录启动独立 mysqld 实例，仅供本项目使用
- 优点：完全不影响用户现有 MySQL 实例与数据
- 缺点：多一个常驻进程

### 路径 D：Docker（当前不可用）

若后续安装 Docker Desktop，直接使用 `deploy/docker-compose.yml`，MySQL 与 Redis 全部容器化，无需触碰本机实例。

> **默认决策**：进入第二阶段时先向用户确认是否提供现有 MySQL 密码；若不便提供，采用 **路径 C（独立实例，端口 3307）** 以零侵入方式推进。

## 4. 部署方案（三套）

### 4.1 方案一：Docker Compose（生产 / 演示推荐）

`deploy/docker-compose.yml` 计划内容：

```yaml
services:
  mysql:
    image: mysql:8.4
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: teaclub
      TZ: Asia/Shanghai
    volumes:
      - mysql-data:/var/lib/mysql
      - ./mysql/conf/my.cnf:/etc/mysql/conf.d/my.cnf:ro
    ports: ["3306:3306"]
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]

  redis:
    image: redis:7-alpine
    command: ["redis-server", "--appendonly", "yes"]
    volumes: [redis-data:/data]
    ports: ["6379:6379"]

  backend:
    build: ./backend
    environment:
      SPRING_PROFILES_ACTIVE: docker
      MYSQL_HOST: mysql
      REDIS_HOST: redis
      TEACLUB_PAYMENT_PROVIDER: mock
    depends_on:
      mysql:
        condition: service_healthy
    ports: ["8080:8080"]

  nginx:
    image: nginx:1.27-alpine
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ../web/dist:/usr/share/nginx/html:ro
    depends_on: [backend]
    ports: ["80:80"]

volumes:
  mysql-data:
  redis-data:
```

### 4.2 方案二：本机直跑（本机当前唯一可实测方案）

```text
1. 启动本机 MySQL 8.4（已在运行）
2. 后端：mvnw spring-boot:run -Dspring-boot.run.profiles=dev
3. Web：  npm run dev     (Vite dev server，代理 /api 到 8080)
4. 小程序：npm run dev:mp-weixin → 微信开发者工具导入 dist/dev/mp-weixin
5. 缓存：teaclub.cache.provider=local      （无需 Redis）
6. 支付：teaclub.payment.provider=mock     （无需商户资质）
```

### 4.3 方案三：云端（超出本期）

不实施。仅保证 `application-prod.yml` 通过环境变量注入全部敏感配置，可直接对接云数据库与云 Redis。
